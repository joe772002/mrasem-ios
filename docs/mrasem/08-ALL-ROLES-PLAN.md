# 08 — خطة «التطبيق الواحد لكل الأدوار» (iOS، نسخة عرض محلية)

> الهدف: نقل **بوابة الإدارة** (النموذج التفاعلي «مراسم — بوابة الإدارة») جوّه تطبيق iPhone، وجمع **كل المستخدمين في تطبيق واحد** مع زر لتبديل المستخدم. أي فعل من مستخدم (مثلاً السائق يضغط «وصلت») يظهر عند باقي المستخدمين المعنيين لحظياً، وكل البيانات **محلية على الجهاز**: مفيش سيرفر ولا API ولا مكتبة جديدة.
>
> **الحالة:** Phase 10 حتى 17 مكتوبين (2026-11-12). نموذج البيانات والصلاحيات وخريطة الشاشات في `09-DATA-MODEL.md`.
>
> الخطة دي بتكمّل بعد Phase 9 (الترقيم من 10). القواعد العامة في `02-RULES.md` سارية، والقواعد الجديدة تحت في قسم «قواعد إضافية».

## 1. المستخدمون والأدوار

| الدور | مين | بيشوف إيه | بيعمل إيه |
|---|---|---|---|
| **الأدمن** | مدير من فريق المراسم | كل البوابة: لوحة التحكم، الوفود، الموارد، الأماكن، الطلبات، الإعدادات | كل الإضافة والتعديل والحذف، التعيينات، التنبيهات، مسح البيانات |
| **المستضيف / المنسق** | منسق مراسم (فريق) | الوفود المسندة له + تابات الفريق الحالية (الزيارة، التغييرات، الطلبات، الأرشيف) | تعديل بيانات الزيارة، التأجيل، الرد على الطلبات، التنبيهات |
| **عضو الوفد** | كل عضو مسجّل في وفد | تابات الضيف الستة الحالية، ببيانات وفده هو | طلب زيارة، سؤال، قائمة الفحص |
| **المرافق** | مرافق معيّن لأعضاء | الوفد اللي معاه: الأعضاء، البرنامج، السيارة، جهات الاتصال | «أبلغ الوفد»، متابعة وصول السائق |
| **السائق** | سائق مربوط بسيارة | «رحلاتي» + الجدول | في الطريق ← **وصلت** ← تم الاستلام ← انتهت |

- **داخل قطر / بالخارج** بقى **صفة للوفد** (`mode`) مش زر في الهيدر. الضيف بيشوف محتوى قطر أو الخارج حسب وفده.
- **تبديل المستخدم:** شاشة «اختر المستخدم» بعد الـ Splash، وزر في الهيدر يفتحها في أي وقت. القائمة مبنية من البيانات نفسها (الأدمن، كل عضو، كل مرافق، كل سائق، كل منسق) ومقسّمة حسب الدور، وجنب كل مستخدم **عدد تنبيهاته غير المقروءة**.

## 2. التزامن بين المستخدمين (على نفس الجهاز)

- **مصدر واحد للحقيقة:** `MrasemStore` واحد بيعرض `CurrentValueSubject<MrasemDatabase>`، وكل الشاشات لكل الأدوار بتقرأ منه (امتداد A5). أي تعديل بيظهر فوراً عند الكل.
- **الأحداث:** كل فعل مهم بيتسجّل كحدث (`ActivityEvent`) ويتوزّع كـ **تنبيه لكل مستخدم معني** (`Notice` + `recipientIds` + `readBy`).

| الفعل | يوصل لمين |
|---|---|
| السائق «في الطريق» / «وصلت» | أعضاء الوفد اللي في العربية + المرافق + المستضيف + الأدمن |
| تعديل/تأجيل فقرة | أعضاء الوفد + المرافق + سائق الفقرة (لو «إشعار الوفد تلقائياً» شغال) |
| طلب زيارة / سؤال من عضو | المستضيف + الأدمن |
| «تم الترتيب» / رد على سؤال | العضو صاحب الطلب + مرافقه |
| تنبيه عام (الكل / المرافقين / السائقين) | حسب الجمهور المختار |
| تغيير السيارة أو السائق أو الغرفة | العضو + السائق القديم والجديد |

- لما تبدّل لمستخدم عنده تنبيهات جديدة: بانر في أول الشاشة («وصل السائق أحمد — لكزس LS · ١٢٣٤٥٦»)، وبطاقة المهمة بتتحدّث (مراحل الوصول)، والـ badge بيتصفّر لما يقرأها.
- **إشعارات iOS المحلية (اختياري، Phase 16):** `UNUserNotificationCenter` محلي من غير سيرفر، بيطلع لما الحدث يخص مستخدم مش هو الحالي. الافتراضي: مقفول، وتنبيهات جوّه التطبيق بس.

## 3. البيانات (محلية بالكامل)

- **التخزين:** ملف JSON واحد (`Codable`) في `Application Support/Mrasem/database.json`، بكتابة ذرّية (atomic) و`schemaVersion`. مفيش Core Data/SwiftData عشان: سهل يتختبر على الـ CI، ومفيش migrations مخفية، وبيتراجع من غير Xcode. (البديل SwiftData متاح لو حبيت، بس مخاطرته أعلى من غير Mac.)
- **الكيانات** (مأخوذة من البوابة + اللي محتاجه الضيف):
  `Delegation` · `Member` · `Escort` · `Driver` · `Car` · `Place` (فندق/مطعم/مزار/جهة) · `ProgramItem` · `GuestRequest` · `Notice` · `TeamUser` (أدمن/منسق/مشاهد) · `TripStatus` · `ChecklistState` · `ChatMessage` · `Preferences` · `CurrentUser`.
- **من غير بيانات افتراضية:** أول تشغيل بيسأل: «ابدأ فارغ» أو «حمّل بيانات العرض» (بيانات البوابة + بيانات مراسم الحالية). وفي الإعدادات:
  - حذف أي عنصر لوحده (مع تأكيد، والحذف بيتسلسل: حذف وفد ← أعضاؤه وبرنامجه وطلباته وتنبيهاته).
  - «مسح بيانات وفد» · «مسح كل البيانات» · «إعادة تحميل بيانات العرض».
  - أول أدمن بيتعمل تلقائياً في التطبيق الفاضي عشان تقدر تدخل.
- **محتوى الضيف اللي مش في البوابة** (الطقس، زي اليوم، قائمة الفحص، الأعراف، الخدمات، دليل البروتوكول): بيبقى **محتوى مرجعي لكل وجهة** يعدّله الأدمن من «الإعدادات ← محتوى الوجهة»، وممكن يتمسح زي أي بيانات.

## 4. نقل البوابة للموبايل

| البوابة (ويب) | الموبايل |
|---|---|
| القائمة الجانبية (6 أقسام) | Bottom bar للأدمن: **الرئيسية · الوفود · الموارد · الأماكن · الطلبات** + الإعدادات من زر الهيدر |
| الجداول | قوائم كروت (سطر لكل عضو/سائق) + شاشة تفاصيل |
| `<select>` جوّه الجدول | Sheet اختيار (Menu) |
| الـ modal | `sheet` بنموذج |
| جدول التعيينات (شبكة ساعات) | قائمة أفقية لكل سائق بخانات الساعات مع scroll، والتعارض باللون التحذيري |
| أزرار الأيقونة (تأجيل/تعديل/حذف) | Swipe actions + زرار في التفاصيل |

الألوان والخطوط والمكوّنات من الـ Design System الحالي (قواعد B). اللي مش موجود يتضاف كمكوّن جديد في `Components/` بـ preview.

## 6. قواعد إضافية (G)

- **G1.** مفيش أي اتصال خارجي: لا شبكة ولا API ولا analytics. `APIClient` يفضل مش مستخدم.
- **G2.** كل البيانات من `MrasemStore`. ممنوع `MrasemDemoData` في الشاشات؛ بقى seed اختياري بس.
- **G3.** كل حذف بيتأكد ومتسلسل ومختبر. مفيش عنصر يتيم (عضو بدون وفد، فقرة بسيارة محذوفة → تبقى «بدون سيارة»).
- **G4.** أي فعل يأثر على مستخدم تاني لازم يطلع `Notice` لمستخدمين محددين (مش للوضع كله زي الأول).
- **G5.** الشاشات بتتعامل مع الحالة الفاضية دايماً (مفيش `[0]` ولا `!` على بيانات المستخدم).
- **G6.** تبديل المستخدم مفيهوش باسورد (نسخة عرض)، وده مكتوب في شاشة التبديل.

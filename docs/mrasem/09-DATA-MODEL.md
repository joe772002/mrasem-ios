# 09 — نموذج البيانات والصلاحيات وخريطة الشاشات (Phase 10)

> مرجع Phases 11–18 في خطة `08-ALL-ROLES-PLAN.md`. الكود في `WantProcuration/Mrasem/Store/`.

## 1. الكيانات والعلاقات

```
DestinationRecord ◄──────── DelegationRecord ──────► PlaceRecord (hotelId, venueId)
   (محتوى الوجهة)           │  coordinatorIds ──► TeamUserRecord
                            │
          ┌─────────────────┼─────────────────┬───────────────────┐
          ▼                 ▼                 ▼                   ▼
    MemberRecord      ProgramItemRecord   RequestRecord       NoticeRecord
     │escortId ─► EscortRecord │placeId ─► PlaceRecord  │memberId   │recipients/readBy: [UserRef]
     │carId ─► CarRecord ◄──── │carId                   │placeId
     │            │driverId ─► DriverRecord
     ├─ ChecklistRecord (id = memberId)
     └─ ChatRecord (memberId)
                      ProgramItemRecord ── TripRecord (id = itemId، حالة رحلة السائق)
```

| الكيان | أهم الحقول | ملاحظات |
|---|---|---|
| `DelegationRecord` | الاسم، `mode` (داخل قطر/بالخارج)، الجهة، الفترة، الفندق، الملتقى، الوجهة، المنسقون، الحالة (مسودة/نشط/مؤرشف)، زي اليوم، بطاقة اللقاء القادم | الوضع بقى صفة للوفد |
| `MemberRecord` | الوفد، الاسم، الصفة، المرافق، السيارة، الغرفة، حالة التطبيق، `isHead` | بيانات رئيس الوفد = بطاقة المهمة |
| `EscortRecord` | الاسم، الصفة، الهاتف، مكان الاستقبال | |
| `DriverRecord` / `CarRecord` | السائق (متاح/إجازة) · السيارة (النوع، اللوحة، نوع اللوحة، السائق) | |
| `PlaceRecord` | النوع (فندق/مطعم/مزار/جهة)، الوضع، الوصف، الدقائق، المدة، الوسم، الشخصية الرسمية، تفاصيل المبنى والإحداثيات، الفطور | دليل واحد لكل الوفود |
| `ProgramItemRecord` | الوفد، التاريخ، الوقت، النوع، المكان، الملاحظة، السيارة، `isKey`، `isChanged`، `dressCode` (الزي المطلوب — نص حر اختياري، الأدمن بيملاه من فورم الفقرة، وبيظهر عند الضيف على طرف الصف) | |
| `RequestRecord` | الوفد، العضو، النوع (زيارة/سؤال)، النص، المكان، الحالة، الرد | |
| `NoticeRecord` | الوفد، الجمهور، المستلمون، اللي قروه، المحتوى (`NoticeBody`) | تنبيه لمستخدمين محددين (G4) |
| `TeamUserRecord` | الاسم، الدور (أدمن/منسق/مشاهد) | آخر أدمن ما يتحذفش |
| `DestinationRecord` | الطقس، العملة، الطوارئ، الخدمات، معلومات سريعة، الأعراف، قائمة الفحص، الدليل، أطقم الزي | القرار #4 |
| `PreferencesRecord` | إعدادات البوابة + المظهر + الإشعارات المحلية | |
| `UserRef` | `.team / .member / .escort / .driver` + المعرّف | المستخدم الحالي ومستلمو التنبيهات |

**الملف:** `Application Support/Mrasem/database.json` — JSON مرتب، كتابة ذرّية، `schemaVersion = 1`.
- ملف تالف أو من إصدار أحدث ← يتحفظ نسخة باسم `database.corrupt-<وقت>.json` ونبدأ قاعدة فاضية (من غير ما نكتب فوقه).
- فشل الحفظ ← الحالة في الذاكرة بتفضل صح، والخطأ في `lastSaveError`.

## 2. الحذف المتسلسل (G3)

| بتحذف | اللي بيحصل |
|---|---|
| وفد | أعضاؤه (وكل حاجة تبعهم) + برنامجه + رحلاته + طلباته + تنبيهاته |
| عضو | طلباته، قائمة فحصه، محادثته، ويتشال من مستلمي التنبيهات |
| مرافق | الأعضاء يبقوا «بدون مرافق» |
| سائق | سيارته تبقى «بدون سائق» |
| سيارة | الأعضاء والفقرات يبقوا «بدون سيارة» |
| مكان | الفقرات والطلبات تفقد المرجع، والوفد يفقد الفندق/الملتقى |
| وجهة | الوفود تبقى من غير محتوى وجهة |
| فقرة | حالة رحلتها |
| عضو فريق | يتشال من منسقي الوفود (آخر أدمن ممنوع) |

أي مستخدم بيتحذف وهو المستخدم الحالي ← الحالي يبقى `nil` فتظهر «اختر المستخدم». ولو مفيش أدمن خالص، بيتضاف «مدير النظام» تلقائياً.
